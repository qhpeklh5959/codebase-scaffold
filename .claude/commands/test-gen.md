为指定目标生成测试脚本，达到目标覆盖率。用法：`/test-gen <目标文件或类路径> <覆盖率，如 80>`

---

## Step 1：解析参数

从 `$ARGUMENTS` 中解析：

- `TARGET`：目标文件路径或类名（如 `src/service/UserService.java` 或 `UserService`）
- `COVERAGE`：目标覆盖率百分比（如 `80`，默认为 `80`）

若 TARGET 是类名而非路径，从 `.agent/refs/symbols.md` 中查找对应路径。

## Step 2：加载上下文

读取：

1. `.agent/refs/CODEBASE.md` — 获取测试框架和运行命令
2. `.agent/refs/conventions.md` — 获取测试命名规范、目录位置、Mock 框架
3. `.agent/refs/patterns.md` — 获取标准测试结构模板
4. `.agent/refs/failures.md` — 避免已知测试错误
5. 目标文件本身 — 读取所有公共方法、分支条件、异常路径

## Step 3：分析覆盖点

对目标文件进行静态分析，列出：

- 所有**公共方法**（必须覆盖）
- 每个方法中的**分支点**（if/else/switch/三元运算）
- **异常路径**（try/catch、错误返回）
- **边界条件**（null 检查、空集合、数值边界）
- **外部依赖**（需要 Mock 的接口或服务）

估算达到 `COVERAGE%` 需要覆盖哪些用例。

## Step 4：生成测试代码

按以下要求生成测试文件：

1. 测试文件路径和命名遵循 conventions.md 中的测试规范
2. 使用 patterns.md 中的标准测试结构模板
3. 为每个需要覆盖的路径生成独立的测试方法，命名清晰描述场景
4. 使用 conventions.md 中指定的 Mock 框架 Mock 外部依赖
5. 断言风格与项目一致
6. 测试方法上方注释标注覆盖的分支（如 `// covers: null input path`）

## Step 5：写入并运行

1. 使用 Write 创建测试文件
2. 运行测试命令（从 CODEBASE.md 获取）
3. 运行覆盖率检查命令（从 CODEBASE.md 获取）
4. 解析覆盖率报告，获取当前覆盖率数值

## Step 6：覆盖率不足时的补充循环

若当前覆盖率 < `COVERAGE`：

1. 从覆盖率报告中定位**未覆盖的具体行或分支**
2. 针对未覆盖路径补充测试用例（追加到测试文件）
3. 重新运行并检查覆盖率
4. 重复，最多 3 次补充循环

若 3 次后仍未达标：

- 输出当前覆盖率
- 列出仍未覆盖的路径及其未覆盖原因（如：私有方法、静态依赖难以 Mock）
- 更新 `.agent/refs/failures.md`，记录该场景和限制

## 重试流程（编译/运行失败）

若测试编译失败或运行报错：

1. 解析错误类型
2. 查阅 failures.md
3. 修正后重试，最多 3 次
4. 每次失败更新 failures.md

## 完成输出

- 生成的测试文件路径
- 最终覆盖率（行覆盖 / 分支覆盖）
- 覆盖的用例数量
- 若有未覆盖项，列出原因
